# 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| ID1: zero_speed_stop_required | 旧固件检测到相位 bit4=1。当前固件直接对零速轮关闭输出，不再拒绝该相位配置；升级后应不再出现该旧错误 |
| disable_ack_failed / mode_ack_failed | 检查对应 ID、1 Mbps、外部供电、接线与回包；主控能联网不代表电机供电正常 |
| feedback_read_failed | 指定轮反馈丢失，检查连接与供电 |
| driver_fault | 查看 wheels[].status，按驱动器故障表排除过热、欠压等；状态16为自动限流，不单独视为故障 |
| acceleration_multiplier_zero | 驱动器寄存器86加速度倍数为0，按驱动器资料修复 |
| 松开控制后轮子可自由转动 | 正常：普通停车关闭输出。需要保持当前位置时打开驻坡 |
| 驻坡后按键无效 | 升级到 0.4.0；自动驻坡打开后应正常驾驶，停下后保持电流参数60。保持能力需实测 |
| 步进调试后驾驶设置改变 | 原始调试会交出底盘控制权；下一条底盘运动重新设置运行模式并读取参数 |
| OLED 首行压住第二行 | 更新固件关闭文本换行；超长内容在屏幕边缘裁切，保持4行各8像素 |
| 没有 OLED / TTL Node / IMU | 无需补齐这些设备；底盘只依赖 ID1/ID2，姿态或显示不可用不会阻止运动 |
| watchdog | 运动指令超过默认3000ms未续期，检查网络或上位机发送频率 |

反馈 `ready` 表示上次初始化检查结果，不等于正在使能或永远健康；结合 enabled、state、wheels[].valid、motor_id 和 motor_error 判断。修复后主动发新运动指令，不自动恢复旧动作。

驻坡保持期间电机故障会关闭输出。电源断开或总线断开后无法保证继续保持；在实机上检查保持力及独立停车措施。原始调试状态没有底盘运动心跳保护，结束时必须主动停用驱动器。

## 0.4.0 常见问题

- 停车后仍锁轮：检查 hill_hold/holding/release_pending。关闭自动驻坡后停用会确认寄存器40=0，通信失败会重试；检查反馈和驱动供电，不能把寄存器 ACK 等同于机械结果。
- 高速噪声：UI 和固件上限均为0.32m/s，旧的更高 NVS 配置不再采用。若低速仍异常，检查机械、供电、相位和电流参数。
- OLED 电压不及时变化：为让通信优先，最多每分钟刷新一次，运动或持续控制通信时推迟；无有效缓存显示 -- V。
- 电流为什么不是 A：驱动原始寄存器尚无已确认的安培换算。current_valid=false 表示不可用，不代表零电流。
- CAN 状态等待超时：SDK 需要 ACK 和三个状态分片，固件需0.4.0；检查扩展帧、DLC、节点和序列号。
- USB 查询没有结果：确认使用原生 Type-C USB；Type-C UART 是 UART0，需要1Mbps及 T604 开启回复。参见[USB/UART 教程](usb-cdc.md)。
